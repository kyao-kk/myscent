# MyScent 动态与交互语言 v0.1

- 状态：Draft for Motion Production
- 依赖：视觉主题基线、首发场景与固定资源清单
- 原则：动态服务于操作因果，不服务于炫技

## 1. 动态目标

玩家每次操作都应获得清楚、克制、可理解的反馈：

> 我选了什么 → 我加入了多少 → 配方哪里变化 → 当前是否出现问题 → 下一步可以如何修正。

动态必须让“游戏动作”和“真实配方变化”形成同一件事。

## 2. 首批六种核心动态

### M-01 材料悬停

- 材料瓶轻微抬升；
- 局部边缘光增强；
- 标签符号变清晰；
- 不播放粒子爆发。

建议时长：120–180ms。

### M-02 取用材料

- 瓶体向前移动并轻微放大；
- 滴管或量取器自动靠近；
- 背景轻度压暗；
- 其他材料不同时发光。

建议时长：220–320ms。

### M-03 滴加

- 液滴从滴管落向主容器；
- 液滴颜色对应当前香气积木；
- 落点出现一次液面波纹；
- 数量变化与液滴落下时刻同步提交。

建议时长：350–550ms。

### M-04 混合与计算

- 液体发生一次缓慢旋流；
- 颜色或明度轻微变化；
- 相关属性只显示2—3项短促增减提示；
- 前中后调条平滑过渡，不弹出完整分析大屏。

建议时长：500–900ms。

### M-05 风险与失衡

- 主容器局部颜色或边缘出现不稳定变化；
- 反馈卡显示一个最主要问题；
- 使用琥珀黄表示注意，暗红表示严重冲突；
- 禁止全屏闪红或大量碎裂特效。

建议时长：300–600ms，必要时维持弱循环。

### M-06 平衡与保存

- 液面恢复稳定；
- 主容器出现一次柔和呼吸光；
- 保存成功以短暂金色印记或封蜡符号确认；
- 不生成大型奖杯、评分爆炸或满屏星光。

建议时长：450–800ms。

## 3. 同屏动态限制

- 显著动态最多同时2种；
- 循环动态最多1种；
- 粒子只用于滴加轨迹、微尘和保存确认；
- 粒子数量必须保持稀疏；
- 背景动态不得影响材料识别；
- UI数值变化不得与场景特效争夺注意力。

## 4. 2.5D场景运动

首发采用轻量2.5D板绘场景，而不是完整3D场景。

允许：

- 远中近景微弱视差；
- 窗外云雾缓慢移动；
- 植物轻微摆动；
- 烛火或炼金灯细微变化；
- 桌面局部阴影随操作改变；
- 液体与光效独立动画。

禁止：

- 大幅镜头旋转；
- 持续推拉摇移；
- 所有背景物同时运动；
- 高频粒子和屏幕抖动；
- 影响读数和点击位置的镜头漂移。

## 5. 交互反馈优先级

1. 操作是否被接收；
2. 配方成分和数量是否变化；
3. 香味属性和阶段如何变化；
4. 是否触发遮盖、冲突或失衡；
5. 场景情绪反馈；
6. 装饰性动画。

前四项未完成时，不得先播放装饰性动画。

## 6. 声音建议

首批只需要短音效，不制作完整配乐系统：

- 玻璃轻碰；
- 滴液；
- 液面波纹；
- 纸页与笔记；
- 研钵摩擦；
- 轻微魔法共鸣；
- 风险提示；
- 保存确认。

音效必须短、轻、低侵入，并支持单独关闭。

## 7. 性能与无障碍

- 支持“减少动态”模式；
- 关闭动态后仍能通过文字、图标和数值理解结果；
- 动态不作为唯一的信息载体；
- 移动端优先保证60fps目标，低端设备允许降为30fps；
- 背景视差和粒子可分级关闭；
- 同一命令重试不得重复播放完整成功动画。

## 8. 动态验收

每个动作必须通过以下问题：

- 玩家是否知道自己操作成功？
- 玩家是否看见了真实配方变化？
- 玩家是否理解变化原因？
- 动态是否遮挡中央工作台？
- 动态是否在1秒左右完成主要信息传达？
- 关闭动态后功能是否仍完整？

任何只“看起来华丽”但不能回答上述问题的动态，不进入首发资源包。
