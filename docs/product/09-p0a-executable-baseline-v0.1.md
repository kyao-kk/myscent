# MyScent P0-A 可执行基线与回归验收

- 文档版本：v0.1
- 状态：Draft for Technical Review
- 对应 Issue：#1
- 对应 PR：#2
- 适用阶段：P0-A 因果模型原型

## 1. 本轮完成的收敛

P0-A 不再只拥有“概念公式”，而是形成六个互相约束的正式输入：

1. `specs/scent/scent-blocks.v0.1.json`：24 个香气积木参数；
2. `specs/scent/scent-relations.v0.1.json`：互补、桥接、遮盖、冲突和组规则；
3. `specs/scent/scent-engine.v0.1.json`：唯一可执行计算顺序、公式和阈值；
4. `specs/scent/scent-fixtures.v0.1.json`：15 组固定回归测试；
5. `specs/workbench/formula-command-protocol.v0.1.json`：玩家操作的命令与事件协议；
6. `specs/workbench/workbench-state-machine.v0.1.json`：配方、分析、持久化与场景状态机。

这六份规格共同解决一个核心问题：

> 前端看到的滴加、减弱、替换和撤销，必须能够通过同一套命令改变配方聚合；配方聚合必须通过唯一版本的算法产生确定结果；结果必须能够被测试、解释、回放和跨场景复用。

## 2. P0-A 的最小实现边界

P0-A 只实现一个低保真的精密实验室工作台，不要求美术成品。

### 必须实现

- 新建一份空配方；
- 从 24 个积木中查看并加入材料；
- 增加、减少、设定、替换和移除材料；
- 撤销最近操作；
- 保存相对份数，不把它冒充真实生产百分比；
- 触发即时分析和完整数字闻香；
- 输出 8 项属性、前中后调、主体、清晰度、复杂度、连续性、平衡度和置信度；
- 输出命中的关系、问题、证据和最多 3 个可执行调整方向；
- 保存版本快照；
- 从历史版本创建分支；
- 封存完成版本；
- 使用固定夹具执行自动化回归测试。

### 暂不实现

- 高完成度 3D 或重动画场景；
- 魔法师完整场景；
- 公开社区、关注、评论和交易；
- 真实原料自由录入界面；
- 官方材料包、试香和生产；
- AI 自动决定核心数值；
- 文生视频；
- 真实化学安全结论。

## 3. 唯一计算基线

`specs/scent/scent-engine.v0.1.json` 是 P0-A 数值行为的唯一来源。

实现不得自行修改：

- `gamma = 0.85`；
- 遮盖、互补、桥接和冲突的执行顺序；
- 贡献归一化方式；
- 阶段计算方式；
- clarity、complexity、continuity、balance 和 confidence 的权重；
- 问题触发阈值；
- 输出舍入位数；
- 公式哈希排除场景字段的规则。

需要调整时必须：

1. 新增引擎版本；
2. 更新回归夹具期望结果；
3. 给出差异报告；
4. 保留旧版本回放能力；
5. 经过项目负责人确认后才能替代当前版本。

## 4. 回归测试分组

### 4.1 数值正确性

- T-001 单一材料；
- T-002 双材料互补；
- T-003 定向遮盖；
- T-004 甜厚过载；
- T-005 中段缺失；
- T-006 尾段不足；
- T-007 复杂但清晰；
- T-008 简单但模糊。

这些测试使用 `0.0001` 数值容差。

### 4.2 操作因果

- T-009 撤销后恢复完全相同结果；
- T-010 替换后旧材料贡献完全消失；
- T-011 场景切换不改变数值。

### 4.3 稳定性和边界

- T-012 外购材料数据不完整时降低置信度；
- T-013 同输入连续运行 100 次结果一致；
- T-014 极端份数不出现 NaN、Infinity 或随机抖动；
- T-015 历史规则版本可以回放。

## 5. 命令处理要求

所有配方修改通过 `formula-command-protocol.v0.1.json` 执行。

### 5.1 不允许直接改数据库行

应用服务不得绕过命令处理器直接修改 `FormulaComponent`。

否则会破坏：

- revision；
- 操作日志；
- 撤销；
- 版本回放；
- 公式哈希；
- 分析新鲜度；
- 并发冲突检测。

### 5.2 乐观并发

每个修改命令携带 `expected_revision`。

当客户端版本落后时：

- 返回 `REVISION_CONFLICT`；
- 返回远端最新 revision 和差异摘要；
- 不自动合并比例；
- 由用户明确选择重新载入或把本地状态另存为分支。

香水配方中的静默合并不可接受，因为它会在用户不知情时改变比例。

### 5.3 幂等

网络重试必须复用 `idempotency_key`。

同一个幂等键：

- 相同命令返回原结果；
- 不重复增加材料；
- 不重复增加 revision；
- 若载荷不同，返回 `DUPLICATE_COMMAND_MISMATCH`。

## 6. 状态机要求

工作台不是一个单状态页面，而是四个并行区域：

1. **配方生命周期**：空配方、编辑、分析完成、版本保存、封存；
2. **分析状态**：无结果、过期、即时分析中、完整分析中、最新、可恢复失败；
3. **持久化状态**：仅本地、同步中、已同步、版本冲突、可恢复失败；
4. **场景表现状态**：实验室、魔法师及未来场景。

关键约束：

- 配方修改后，旧分析立即标记为过期；
- 旧分析可以展示，但不得冒充当前结果；
- 分析失败不能丢配方；
- 场景切换不能增加配方 revision；
- 封存后不能直接修改，只能建立分支；
- 撤销写入补偿事件，不删除历史事件。

## 7. 输出契约最低要求

完整分析结果至少返回：

```json
{
  "formula_id": "F-001",
  "formula_revision": 7,
  "formula_hash": "...",
  "engine_version": "0.1.0",
  "block_library_version": "0.1.0",
  "relation_library_version": "0.1.0",
  "normalized_components": [],
  "stages": {},
  "attributes": {},
  "primary_components": [],
  "family_contributions": [],
  "clarity": 0.0,
  "complexity": 0.0,
  "continuity": 0.0,
  "balance": 0.0,
  "relations": [],
  "problems": [],
  "suggestions": [],
  "confidence": {},
  "evidence_refs": [],
  "prediction_disclaimer_version": "0.1"
}
```

前端不得从解释文案反推数值。

## 8. 建议生成的约束

建议由问题代码和规则证据生成标准动作，再由场景翻译。

例如标准建议：

```text
decrease_component SB-GO-02 by one_step
```

实验室表达：

> 将焦糖甜感组分下调一格，预计甜度和厚重度降低。

魔法师表达：

> 收回一滴糖雾，让被遮住的气息重新显形。

两者必须拥有：

- 相同目标材料；
- 相同动作类型；
- 相同预期数值方向；
- 相同证据引用。

## 9. P0-A 验收门槛

同时满足以下条件才允许进入 P0-B：

1. 15 个固定夹具全部通过；
2. T-013 连续 100 次执行结果一致；
3. 所有修改命令支持幂等与 revision 冲突；
4. 撤销后公式哈希与原状态一致；
5. 场景 ID 不进入公式哈希；
6. 分析失败和刷新不丢配方；
7. 所有问题至少有一条证据和一个可执行建议；
8. 无权限接口不返回生产层字段；
9. 旧分析不会被标记为当前；
10. 至少完成一轮产品、技术和有经验香水用户的参数评审。

## 10. 当前风险

### 参数看起来精确，但本质仍是首版启发式假设

应对：持续显示预测边界，禁止将小数位包装成科学测量精度。

### 关系矩阵覆盖有限

应对：置信度必须体现覆盖不足；不得让语言模型编造缺失关系。

### 前端为了流畅自行近似计算

应对：允许即时分析使用同一引擎的轻量路径，但不能使用另一套公式。

### 用户把相对份数理解为可直接购买的百分比

应对：P0-A 统一显示“相对份数”；真实材料和生产版本另行建立。

### 状态过多导致实现复杂

应对：状态机可以由一个聚合状态和三个子状态字段实现，不要求引入重型状态机框架，但行为必须符合规格。
