# MyScent 产品愿景与定位

- 文档版本：v0.2
- 状态：Draft
- 对应 Issue：#1
- 核心定位：**让调香像游戏一样可玩，让游戏中的每一步又真实影响香水结果。**
- 衍生传播语：**把故事做成香水。**

## 1. 产品愿景

MyScent 是一款把**制作场景、调配仪式、香味计算和现实调香逻辑**连接起来的数字调香产品。

它要打破两种常见产品之间的墙：

- 一边是偏实际的调香工具：参数真实，但像表格、课程或专业软件，普通用户难以进入；
- 一边是偏娱乐的调香游戏：场景好看、操作有趣，但材料和动作不会真正影响香味结果。

MyScent 的核心不是在两者之间取折中，而是建立双向映射：

> 用户在游戏化制作场景中执行的每一次取料、滴加、混合、静置、试闻和调整，都会进入真实的数字配方与香味计算；系统给出的香调、属性、冲突和修改建议，又会回到场景中，变成可感知、可操作的反馈。

故事、香语、自我表达、海报和视频是制作完成后的衍生层。它们可以放大作品价值，但不替代制作玩法与香味计算。

## 2. 产品核心定义

MyScent 是一个“可玩的数字调香台”。

核心闭环为：

`进入制作场景 → 选择或发现材料 → 执行调配动作 → 系统实时计算香味变化 → 通过视觉、声音和仪器反馈感知结果 → 调整配方 → 完成香水 → 查看前中后调与整体预测 → 可选生成故事和传播内容 → 保存、分享或现实兑现`

这个闭环必须同时满足：

1. **有游戏感**：场景、身份、器具、动作、反馈、探索和成长让制作过程值得玩；
2. **有实际依据**：材料角色、相对比例、挥发层次、兼容关系和香气属性真实参与结果计算；
3. **有因果关系**：同样的场景中，不同操作必须得到不同结果；同一配方在不同场景皮肤下，核心香味结果不能被随意改变；
4. **可逐步现实化**：数字配方、版本和材料映射能够在后续连接试香、材料包和合作生产。

## 3. 要打破的三面墙

### 3.1 工具与游戏之间的墙

传统工具要求用户先懂调香；传统游戏常把调香简化为选择题。

MyScent 要让用户先通过游戏动作进入，再在操作中自然理解：

- 为什么某些材料适合作为前调；
- 为什么比例变化会改变主次；
- 为什么过多主题会互相遮盖；
- 为什么一款香需要开场、主体和留存；
- 为什么“加得更多”不一定“闻得更明显”。

学习不是单独的教程，而嵌入制作行为和反馈中。

### 3.2 场景表现与配方逻辑之间的墙

制作场景不能只是视频滤镜。

不同场景可以改变：

- 器具外观；
- 操作语言；
- 动画与声音；
- 信息展示方式；
- 仪式节奏；
- 引导人格和挑战形式。

但场景中的动作必须映射到统一的调香逻辑。

例如：

- 魔法师场景中的“注入三滴月光露”，对应加入某个透明、冷感、前调倾向的香气积木及其相对量；
- 实验室场景中的“移液 0.3 份清亮组分”，对应同一底层操作；
- 东方香房中的“添一匙清露香材”，仍指向同一配方变更。

表演语言不同，底层因果一致。

### 3.3 数字结果与现实香水之间的墙

MVP 输出是数字香气预测，不冒充真实试闻。

但系统从一开始就要记录：

- 材料或香气积木 ID；
- 相对比例；
- 前中后调角色；
- 属性向量；
- 兼容与冲突规则；
- 模型、规则和积木库版本；
- 用户每一步操作；
- 作品版本差异；
- 未来真实材料映射状态。

这样产品后续才能把游戏中的作品逐步映射到真实试香，而不是重新做一套无关的生产系统。

## 4. 产品价值层级

### 4.1 第一层：制作场景与调配仪式

这是产品第一重心。

用户要获得：

- 进入另一种制作身份的代入感；
- 对器具、材料和空间的探索感；
- 取料、滴加、称量、摇匀、加热表现、静置、观察等动作反馈；
- 通过液体、雾气、光影、声音、仪表或符号理解变化；
- 制作失败、失衡、修正和重新实验的过程；
- 完成一款作品时的仪式感和成就感。

### 4.2 第二层：香味计算与配方结果

这是产品可信度和长期价值的基础。

系统至少计算和反馈：

- 前调、中调、后调结构；
- 主香调与辅助香调；
- 甜度、清新度、冷暖、轻重、柔锐、透明度、扩散和留香倾向；
- 材料的增强、遮盖、冲突与失衡；
- 当前作品的清晰度和复杂度；
- 下一步可操作的调整建议；
- 不同版本之间的变化原因；
- 结果置信度与数字预测边界。

### 4.3 第三层：玩家成长

普通玩家、有经验玩家和高级玩家不是三个割裂产品，而是同一制作系统的逐层揭示。

#### 普通玩家

- 看到气味意象和直观器具；
- 通过拖放、滴加、选择强弱完成制作；
- 系统隐藏复杂参数，但不替用户完成全部操作；
- 通过反馈逐渐理解香调知识。

#### 有经验玩家

- 看到香气家族、前中后调位置和相对比例；
- 可以替换积木、调整结构和比较版本；
- 获得更明确的冲突和遮盖解释。

#### 高级玩家

- 后续看到真实原料、稀释度、百分比、克数、成本、挥发特征、限制和生产映射；
- 可以使用更精确的工具与记录方式；
- 自由度和安全、合规、可生产校验同步增加。

### 4.4 第四层：故事、自我表达与传播

这是衍生层，不是核心制作的前置门槛。

完成香水后，用户可以选择：

- 为作品命名；
- 写下或生成香语；
- 写故事或人物设定；
- 生成海报和制作过程短视频；
- 发布、评论、收藏、分享；
- 后续出售配方、试香或成品。

用户即使不写故事、不公开表达，也必须能够完整享受制作、计算、调整和收藏配方的核心体验。

## 5. 场景不是皮肤，而是交互语言

MVP 首批制作世界可包括：

### 5.1 魔法师 / 炼金术士

- 器具：药剂瓶、坩埚、古书、滴管、符号盘；
- 反馈：液体发光、烟雾、符号稳定度、魔力层次；
- 声音：玻璃、火焰、翻书、液滴、低频空间声；
- 底层映射：比例、层次、冲突、稳定性和香气属性。

### 5.2 精密实验室

- 器具：移液器、烧杯、量筒、电子秤、分析屏；
- 反馈：曲线、数值、仪器提示、透明度和稳定状态；
- 声音：按键、液滴、玻璃、机械和电子提示；
- 底层映射：更直接地展示配方、比例和预测结果。

### 5.3 东方香房

- 器具：木案、香材盒、铜炉、研钵、纸笺和小秤；
- 反馈：研磨程度、香气层次、烟气、纸上配伍记录；
- 声音：研磨、木器、纸张、风、水和器皿；
- 底层映射：同一套材料、比例、层次和兼容规则。

### 5.4 自然工坊

- 器具：植物采集盘、露水瓶、木质容器、晾置架；
- 反馈：植物状态、水汽、风、光照和香气扩散表现；
- 声音：叶片、水滴、木器、风和远处环境声；
- 底层映射：同一套香气积木和配方计算。

科学狂人可作为后续高戏剧性场景，但不得通过危险化学步骤制造玩法。

## 6. 核心系统关系

MyScent 的核心不是“调香引擎 + 内容生成 + 社区”三个并列模块，而是以下主次结构：

1. **制作体验层**：场景、器具、动作、仪式、动画、音效；
2. **配方与香味计算层**：材料、比例、前中后调、属性、规则、预测；
3. **反馈桥接层**：把计算结果转为场景内可感知反馈，把玩家动作转为配方变更；
4. **作品记录层**：保存配方、操作过程、版本和结果；
5. **衍生内容层**：名称、香语、故事、海报和视频；
6. **社区与交易层**：发布、评论、收藏、配方交易和现实兑现。

任何阶段都不得让第 5、6 层反过来挤压前三层。

## 7. 核心产品原则

### 7.1 每个动作必须有配方意义

不能存在大量只为好看、对结果毫无影响的伪操作。装饰动作可以存在，但必须与核心动作明确区分。

### 7.2 每个计算结果必须可被感知

不能只在最后给出一张雷达图。甜度升高、结构变浑、前调过强、主体被遮盖等变化，应尽可能在制作场景中被视觉、声音、仪器或助手反馈表现出来。

### 7.3 场景不篡改底层因果

场景可以改变表现和操作语言，不能让相同配方仅因选择了不同主题就得到完全不同的香味结论。

### 7.4 先可玩，再逐步专业

普通用户先通过动作和反馈理解，专业参数按层级逐步揭示，避免一开始变成专业表格软件。

### 7.5 预测而非绝对计算

系统必须明确结果是数字预测。真实原料、浓度、熟化、环境和个体感知会影响实际气味。

### 7.6 香水本身优先

场景、故事和传播内容最终都要服务于制作过程和香味作品，不能让产品退化为换皮短视频生成器。

## 8. MVP 首要验证

MVP 首先验证的不是用户是否愿意写故事，而是：

1. 用户是否愿意在制作场景中持续完成一轮调配；
2. 用户是否能感知自己的操作确实改变了香味结果；
3. 场景反馈是否帮助普通用户理解抽象香气变化；
4. 用户是否愿意主动调整、试错和制作第二个版本；
5. 不同经验层级是否都能获得合适的控制感；
6. 制作完成后，用户是否愿意保存、分享或进一步现实试香。

## 9. 长期愿景

MyScent 长期可能成长为：

- 一款兼具游戏体验和实际调香逻辑的个人香水制作产品；
- 一个把虚拟配方逐步映射为真实试香与成品的平台；
- 一个面向调香工作室、品牌和门店的场景化数字调香系统；
- 一套连接“玩家动作—数字配方—香味预测—真实试香—反馈修正”的数据基础设施。

长期护城河不是单次生成故事或视频，而是：

> **让每一次可玩的调配动作都具有真实的香味因果，并持续缩短数字制作与现实香水之间的距离。**
