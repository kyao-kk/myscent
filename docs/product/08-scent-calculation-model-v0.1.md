# MyScent 香味计算规则模型 v0.1

- 文档状态：Draft for Technical Review
- 对应 Issue：#1
- 对应 PR：#2
- 适用阶段：P0-A 因果模型原型
- 上游文档：`02-mvp-prd-v0.2.md`、`04-scent-blocks-v0.1.md`、`07-mvp-prd-v0.2-review-v0.1.md`
- 目标：定义一个确定性、可解释、可版本化的数字香气预测模型，使玩家动作真实改变配方结果

---

## 1. 模型定位

本模型不是：

- 真实分子级化学模拟；
- 对实际人体闻香结果的绝对预测；
- 由语言模型自由描述出来的香调文本；
- 可以直接替代试香和专业生产验证的公式。

本模型是：

> 一套基于香气积木属性、相对比例、阶段倾向、强度、互补、桥接、遮盖和冲突规则的数字香气计算系统。

它必须满足：

1. 同样输入、同样规则版本得到同样结果；
2. 改变材料或比例会产生可追溯变化；
3. 每项主要结果能指出证据；
4. 场景只改变表达，不改变计算；
5. 数据缺失时降低置信度，不编造确定结论；
6. 规则、参数和结果均可版本化与回归测试。

## 2. 标准尺度

### 2.1 内部数值范围

除特殊说明外，内部属性使用 `0.0 ～ 1.0`。

用户界面可转换为：

- 0～100；
- 低 / 中 / 高；
- 场景仪表、符号或视觉反馈。

### 2.2 八项核心属性

| 属性键 | 0.0 含义 | 1.0 含义 |
|---|---|---|
| sweetness | 不甜、干燥、苦 | 高甜、糖感、蜜感 |
| freshness | 沉闷、陈厚 | 清新、明亮、空气感 |
| warmth | 冷、凉、距离感 | 暖、热、包裹感 |
| weight | 轻盈、漂浮 | 厚重、浓密 |
| softness | 锐利、尖、干脆 | 柔和、圆润、顺滑 |
| transparency | 浑厚、不透明 | 透明、空灵、留白 |
| diffusion | 贴肤、低扩散 | 高扩散、存在感强 |
| longevity | 短暂、快速消散 | 长久、尾段支撑强 |

### 2.3 派生指标

- clarity：主体清晰度；
- complexity：结构复杂度；
- continuity：前中后段连续性；
- balance：整体平衡度；
- confidence：计算置信度。

派生指标不直接存入香气积木基础向量，由配方计算得出。

## 3. 香气积木参数结构

每个 `ScentBlock` 必须具有以下计算字段：

```json
{
  "id": "SB-CA-03",
  "version": "0.1",
  "family": "citrus_air",
  "attribute_vector": {
    "sweetness": 0.10,
    "freshness": 0.92,
    "warmth": 0.18,
    "weight": 0.12,
    "softness": 0.58,
    "transparency": 0.95,
    "diffusion": 0.62,
    "longevity": 0.22
  },
  "intensity": 0.75,
  "stage_weights": {
    "top": 0.80,
    "heart": 0.18,
    "base": 0.02
  },
  "role_tags": ["atmosphere", "opening", "brightener"],
  "data_quality": 0.85,
  "production_mapping_status": "unverified"
}
```

### 3.1 intensity

`intensity` 表示相同相对份数下，该积木对整体结果的潜在支配强度。

范围：`0.30 ～ 1.50`。

- 低强度积木需要更高比例才能成为主体；
- 高强度积木少量也可能产生明显影响；
- 不允许所有积木默认相同强度。

### 3.2 stage_weights

`top + heart + base = 1.0`。

表示积木在数字预测中的阶段倾向，不代表精确真实挥发曲线。

### 3.3 data_quality

用于置信度计算：

- 1.00：平台规则完整、组合测试充分；
- 0.70～0.99：基础数据完整，部分组合仍需验证；
- 0.40～0.69：实验性积木或映射有限；
- 0.00～0.39：用户自录或数据严重缺失。

## 4. 配方输入

### 4.1 相对份数

用户操作转换为非负相对份数 `q_i`。

归一化：

`p_i = q_i / Σq`

其中：

- `p_i` 为材料在当前数字配方中的归一化比例；
- `Σp_i = 1.0`；
- MVP 不将 `p_i` 直接宣称为真实生产百分比。

### 4.2 有效强度

直接使用比例会低估高强度材料，定义：

`e_i = p_i^γ × intensity_i`

P0-A 建议初始参数：

- `γ = 0.85`

目的：

- 允许少量高强度材料影响结果；
- 避免极小比例完全失去作用；
- 后续通过测试调整。

归一化有效贡献：

`n_i = e_i / Σe`

### 4.3 操作顺序

P0-A 默认：

- 添加顺序记录但不影响核心属性；
- 添加顺序用于操作回放、版本解释和未来工艺扩展；
- 不得在没有验证依据时声称“先加A再加B一定改变最终香味”。

## 5. 基础属性计算

对每个核心属性 `d`：

`A_base[d] = Σ(n_i × V_i[d])`

其中：

- `V_i[d]` 为积木属性值；
- `n_i` 为归一化有效贡献。

基础属性之后依次应用：

1. 互补修正；
2. 遮盖修正；
3. 冲突修正；
4. 过度复杂修正；
5. 极端值软压缩。

最终：

`A_final[d] = softClamp(A_adjusted[d], 0, 1)`

### 5.1 softClamp

避免多个规则叠加后数值硬撞到0或1。

P0-A 可采用简单方式：

- 小于0时缓慢逼近0；
- 大于1时缓慢逼近1；
- 或使用可解释的分段压缩函数。

具体实现必须写入规则版本，不能隐式修改。

## 6. 前中后调计算

### 6.1 阶段贡献

对阶段 `s ∈ {top, heart, base}`：

`C_i,s = e_i × stage_weight_i,s`

阶段内归一化：

`N_i,s = C_i,s / ΣC_s`

### 6.2 阶段主体

每个阶段输出：

- 第一主体；
- 第二主体；
- 其他辅助；
- 阶段强度；
- 阶段清晰度。

建议阈值：

- 第一主体贡献 ≥ 0.35：可称为明确主体；
- 第一主体与第二主体差值 ≥ 0.12：主体较清晰；
- 前两项合计 ≥ 0.60：阶段结构集中；
- 若没有任何一项 ≥ 0.25：阶段偏分散。

阈值均需通过测试校正。

### 6.3 阶段存在性

阶段总有效量：

`S_s = ΣC_i,s`

将三个阶段归一化后判断：

- 前段不足；
- 中段不足；
- 尾段不足；
- 某一阶段过度支配。

### 6.4 连续性

连续性由以下因素构成：

- 前与中是否存在共同家族或桥接积木；
- 中与后是否存在共同家族或桥接积木；
- 阶段之间是否出现完全割裂的高冲突组合；
- 中段是否承担过渡。

概念公式：

`continuity = 0.4 × topHeartBridge + 0.4 × heartBaseBridge + 0.2 × middleSupport - conflictPenalty`

## 7. 主体与支配关系

### 7.1 全局主体

全局贡献排序基于 `n_i`。

输出：

- primary_component；
- secondary_component；
- supporting_components。

### 7.2 主体差距

`dominance_gap = n_1 - n_2`

初始解释：

- ≥ 0.20：主体非常明确；
- 0.10～0.19：主体清楚；
- 0.04～0.09：双主体或轻度竞争；
- < 0.04：主体竞争明显。

### 7.3 家族主体

将同一家族的 `n_i` 汇总，得到家族贡献。

用于避免：

- 一个家族由多个低比例积木构成，却被误判为没有主体；
- 单个高强度修饰材料被误判为整体香调家族。

最终主香调同时参考：

- 单积木贡献；
- 家族总贡献；
- 角色标签；
- 遮盖关系。

---

## 8. 复杂度

### 8.1 成分分布熵

使用归一化 Shannon entropy：

`H = -Σ(n_i × ln(n_i)) / ln(k)`

其中 `k` 为有效材料数量。

- 接近0：少数材料高度支配；
- 接近1：多个材料贡献接近。

### 8.2 家族多样性

`family_diversity = 有效家族数 / 最大建议家族数`

P0-A 最大建议家族数可设为5。

### 8.3 复杂度总分

`complexity = 0.55 × H + 0.30 × family_diversity + 0.15 × interaction_density`

`interaction_density` 表示当前命中的互补、遮盖和冲突关系密度。

### 8.4 解释区间

- 0.00～0.30：简洁；
- 0.31～0.55：适中；
- 0.56～0.75：复杂；
- 0.76～1.00：高度复杂。

复杂不自动等于差，需要结合清晰度判断。

---

## 9. 清晰度

### 9.1 构成

`clarity = 0.30 × dominance + 0.20 × family_coherence + 0.20 × continuity + 0.15 × stage_balance + 0.15 × low_masking - penalties`

其中：

- dominance：主体差距；
- family_coherence：主家族是否集中；
- continuity：阶段连续性；
- stage_balance：三阶段是否缺失；
- low_masking：主体未被遮盖程度；
- penalties：冲突、主题过多和极端支配惩罚。

### 9.2 输出等级

- ≥ 0.75：清晰；
- 0.55～0.74：基本清晰；
- 0.35～0.54：模糊；
- < 0.35：过度混乱或主体缺失。

### 9.3 复杂但清晰

模型必须允许：

- 高复杂度 + 高清晰度；
- 低复杂度 + 低清晰度。

不能简单把材料多等同于失败。

## 10. 成对规则矩阵

每对积木可具有方向性规则：

```json
{
  "source": "SB-X",
  "target": "SB-Y",
  "relation": "masking",
  "strength": 0.30,
  "threshold": 0.08,
  "affected_attributes": ["freshness", "transparency"],
  "evidence": "RULE-MASK-001"
}
```

### 10.1 synergy 互补

作用：

- 提升某些属性；
- 提升家族连贯性；
- 提升阶段连续性。

计算概念：

`synergy_effect = min(n_i, n_j) × strength`

### 10.2 bridge 桥接

作用：

- 增加前中或中后连续性；
- 不一定直接提高核心属性。

### 10.3 masking 遮盖

方向性：A可能遮盖B，但B不一定同等遮盖A。

概念：

`masking_effect(A→B) = max(0, n_A - threshold) × strength`

结果：

- 降低B的可感知贡献；
- 产生解释证据；
- 可能降低主体清晰度。

### 10.4 conflict 冲突

作用：

- 降低清晰度；
- 增加复杂度；
- 触发主题割裂；
- 必要时调整属性。

冲突不是安全禁用，也不是绝对不能组合。

### 10.5 规则优先级

建议顺序：

1. 数据有效性；
2. 强度和比例；
3. 遮盖；
4. 互补；
5. 桥接；
6. 冲突；
7. 整体复杂度和清晰度；
8. 建议生成。

顺序必须固定并版本化。

## 11. 问题检测规则

## 11.1 过甜

初始触发条件示例：

- `sweetness ≥ 0.78`；
- 且甜感家族有效贡献 ≥ 0.35；
- 或甜感材料同时遮盖清新/绿意主体。

可执行方向：

- 减弱主要甜感材料；
- 增加清苦或清新桥接；
- 增加干燥木质支撑。

### 11.2 过厚

- `weight ≥ 0.78`；
- `transparency ≤ 0.28`；
- 后调贡献过度集中。

### 11.3 开场太尖

- 前段锐利材料贡献过高；
- softness过低；
- 前段缺少柔和或空气桥接。

### 11.4 主体被遮盖

- 某主体在未应用遮盖前为第一贡献；
- 应用遮盖后下降超过设定阈值；
- 或主体贡献低于第二材料。

必须指出：

- 遮盖者；
- 被遮盖者；
- 影响程度；
- 可修正动作。

### 11.5 中段缺失

- heart阶段归一化贡献低于阈值；
- 或中段没有任何明确主体；
- 或前段与后段冲突且缺乏桥接。

### 11.6 尾段不足

- base阶段贡献不足；
- longevity低；
- 缺少后调支撑积木。

### 11.7 主题过多

- 有效家族数超过建议值；
- 多个家族贡献接近；
- clarity低且complexity高。

### 11.8 冷鲜与暖甜拉扯

- freshness和warmth/sweetness都高；
- 对应家族存在冲突规则；
- 缺少中性桥接材料。

该状态可以是实验性风格，不自动判定失败。

## 12. 建议生成

### 12.1 原则

- 每次最多3个方向；
- 每个方向必须引用规则证据；
- 建议必须能转化为玩家动作；
- 不自动静默修改；
- 允许多个正确方向；
- 不保证建议后一定变“更好”，只说明预期变化。

### 12.2 建议结构

```json
{
  "suggestion_id": "SUG-001",
  "problem": "too_sweet",
  "action_type": "decrease_component",
  "target": "SB-SW-01",
  "expected_changes": {
    "sweetness": -0.12,
    "transparency": 0.05
  },
  "evidence_refs": ["RULE-SWEET-001", "RULE-MASK-004"],
  "confidence": 0.82
}
```

### 12.3 场景转译

建议先由规则层生成标准动作，再由场景层翻译。

标准动作：

- `decrease_component SB-SW-01 by one_step`

实验室：

- “将甜感组分下调一格。”

魔法师：

- “收回一滴糖雾，让主药剂重新显形。”

底层目标和预期变化不变。

## 13. 置信度

### 13.1 构成

`confidence = 0.30 × data_completeness + 0.25 × rule_coverage + 0.20 × mapping_quality + 0.15 × in_domain + 0.10 × version_stability`

### 13.2 因素

- data_completeness：积木参数是否完整；
- rule_coverage：当前主要关系是否被规则覆盖；
- mapping_quality：真实材料或外购材料映射质量；
- in_domain：是否处于24个积木和建议组合范围内；
- version_stability：当前规则版本是否通过回归测试。

### 13.3 等级

- ≥ 0.80：高；
- 0.55～0.79：中；
- < 0.55：低。

### 13.4 降低置信度的情况

- 用户自录材料缺少浓度或类型；
- 使用未验证映射；
- 规则矩阵没有覆盖主要材料关系；
- 材料数量明显超出建议范围；
- 配方结构落在测试域外。

置信度低不禁止实验，但禁止使用绝对措辞。

---

## 14. 确定性与随机性

### 14.1 核心计算

核心数值必须确定性：

- 同样输入；
- 同样规则版本；
- 同样积木库版本；
- 同样计算参数；

必须得到同样结果。

### 14.2 允许变化的内容

可以变化：

- 解释措辞；
- 场景对白；
- 名称和香语候选；
- 海报和视频内容。

但变化不得反向改写核心数值。

### 14.3 随机种子

若场景动效或衍生内容使用随机性，记录 `seed`，以便回放和审计。

## 16. 操作与增量计算

### 16.1 操作输入

核心操作：

- add_component；
- increase_component；
- decrease_component；
- remove_component；
- replace_component；
- undo_operation；
- analyze_formula。

### 16.2 简化即时反馈

每次操作后可先计算：

- 受影响的属性；
- 主体是否变化；
- 是否触发严重规则；
- 当前阶段变化。

### 16.3 完整分析

玩家触发数字闻香时计算全部结果。

这样可以：

- 减少频繁完整计算；
- 保持操作流畅；
- 让“分析”本身成为仪式动作。

## 17. 回归测试样例

至少建立以下固定测试配方。

### T-001 单一材料

目的：验证属性与阶段完全来自该积木。

### T-002 两个互补材料

目的：验证互补规则与属性增益。

### T-003 遮盖关系

目的：高强度材料加入后，原主体可感知贡献下降，并产生证据。

### T-004 过甜

目的：触发过甜规则，并给出减弱、清苦或干燥支撑建议。

### T-005 中段缺失

目的：只有前调和后调时，识别中段不足。

### T-006 尾段不足

目的：全部为前中段积木时，识别留存支撑不足。

### T-007 复杂但清晰

目的：多个材料通过桥接和主家族维持高清晰度。

### T-008 简单但模糊

目的：两个贡献接近且冲突的材料可形成低复杂度、低清晰度。

### T-009 撤销

目的：撤销后计算结果与操作前完全一致。

### T-010 替换

目的：替换材料后只反映真实差异，不保留旧材料贡献。

### T-011 跨场景一致

目的：实验室与魔法师调用同一计算输入，数值完全一致。

### T-012 低质量外购材料

目的：数据缺失降低置信度，不伪造高可信结论。

### T-013 同输入确定性

### T-014 极端份数

### T-015 规则版本回放

目的：历史配方使用原规则版本可重现原结果；新版本结果单独保存。
